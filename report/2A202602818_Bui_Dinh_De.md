## 4. Giải thích kỹ thuật

### Luồng baseline

`phase1.py` đọc raw snapshot hoặc gọi Crossref, làm sạch dữ liệu, chạy Quality Gate trước serving, build `papers-baseline`, dùng test set cố định để đánh giá rồi sinh metrics và báo cáo. Nếu Quality Gate fail, pipeline từ chối build serving index.

### Luồng corruption và repair

`corruption_flow.py` tạo corrupted dataset, chạy GX/Freshness nhưng vẫn index và đánh giá để quan sát Silent Failure. Repair không vá từng ô dữ liệu lỗi mà đọc lại `crossref_records.json`, gọi cùng hàm cleaning và build collection mới. Cách này giữ data lineage và làm kết quả lặp lại ổn định.

### Data contract chính

Retrieval yêu cầu các cột `paper_id`, `title`, `summary`, `published`, `authors_joined`, `categories_joined`, `text_for_embedding`, `abs_url`, `pdf_url`. Index từ chối DataFrame rỗng, ID rỗng hoặc embedding text rỗng bằng thông báo rõ ràng.

## 8. Hiểu biết end-to-end

1. Crossref payload được bảo toàn ở raw layer, parse thành `PaperRecord`, chuẩn hóa thành clean schema, kiểm định rồi mới embedding/index.
2. Mỗi câu hỏi có `ground_truth` và `ground_truth_doc_ids`; ID xuất hiện trong top-k tạo retrieval hit, câu trả lời được đo Token F1 và Judge score.
3. Quality checks đo completeness, uniqueness và validity; Freshness đo tỷ lệ records vượt ngưỡng tuổi 180 ngày.
4. Cùng một test set được dùng cho ba trạng thái để chênh lệch metrics chỉ phản ánh thay đổi dữ liệu.
5. Repair thành công khi GX/Freshness trở lại PASS, metrics trở lại baseline và artifacts ổn định khi chạy lại.
